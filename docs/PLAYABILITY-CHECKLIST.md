# Odogwu Empire Playability Gate

**Current priority:** prove the game is enjoyable and understandable on the free
public demo before paying for hosting, a database, staging, or a custom domain.

The game is ready for the owner's sign-off only when a first-time player can join
and finish without the developer explaining what to press.

## First-time player clarity

- [x] A player can create a room with only a display name.
- [x] An invite link opens the correct room and asks the guest to join.
- [x] Lobby chat, token choice, player count, and the host's Start button work.
- [x] The first game opens a complete, mobile-scrollable guide once.
- [x] Landing and in-game guides explain the same rules.
- [x] The large bottom button always names the next required action.
- [ ] Test with three people who have never seen the project; nobody needs verbal
      instructions to complete their first two turns.

## Complete game rules

- [x] Dice, movement, cards, taxes, turn synchronization, and automatic handoff.
- [x] Deterministic two-player simulation reaches a winner.
- [ ] Human playtest: buy and decline a property.
- [ ] Human playtest: complete an auction with two or more bidders.
- [ ] Human playtest: collect rent and complete a colour group.
- [ ] Human playtest: build, sell, mortgage, and unmortgage.
- [ ] Human playtest: accept, reject, and counter a trade.
- [ ] Human playtest: recover from debt and declare bankruptcy.
- [ ] Human playtest: enter and leave Kirikiri by every supported method.
- [ ] Human playtest: finish a game, show the winner, and start a rematch.

## Mobile and connection quality

- [ ] Complete two turns at 360px and 390px widths without horizontal page scroll.
- [ ] The current action, cash, active player, and board position remain readable.
- [ ] Chat, property management, trades, auctions, and debt decisions fit on screen.
- [ ] Disconnect and reconnect both host and guest during a game.
- [ ] Open the sleeping free service from a cold start and show a clear loading state.
- [ ] Verify current Chrome, Safari, and Firefox.

## Owner sign-off

- [ ] Run three complete games with real players.
- [ ] Record every confusing or broken moment instead of explaining around it.
- [ ] Fix every launch-blocking issue and the three most common usability problems.
- [ ] Owner confirms the game meets the desired standard.

Paid-hosting work resumes only after this checklist is signed off.
